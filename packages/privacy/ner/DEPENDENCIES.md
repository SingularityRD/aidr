# Optional inference dependencies

The TypeScript package and the Python artifact/offset tests have no third-party runtime dependencies.
`ner_worker.py` additionally needs an approved CPU PyTorch + Transformers + fast-tokenizer + safetensors environment.
A Windows x64 CPython 3.12 CPU environment was installed and replayed offline on 2026-10-06 using `requirements.windows-py312.lock.txt` and a local wheelhouse. The lock contains the exact wheel SHA-256 values measured for that platform. PyTorch 2.14.1+cpu, Transformers 5.13.0, tokenizers 0.22.2 and safetensors 0.8.0 loaded the pinned public candidates. This is reproducibility evidence for the measured environment, not approval, a security audit or a lock for Linux/other Python versions. See `../docs/MODEL_PROVIDER.md` for installation and qualification.

`requirements.linux-py311.lock.txt` pins a separate 34-wheel CPython 3.11/x86_64 environment. Its fresh hash-checked installation and real candidate inference were executed in the existing glibc 2.36 Linux test container with Docker network mode `none` and read-only package/model mounts. Model smoke boundaries/decisions reproduced the Windows alternative; domain qualification still fails. Neither lock nor the test container is an institution-approved deployment artifact.

## Changing a lock

The two locks are the measured environments above, byte-for-byte (their CRLF digests are recorded in `../docs/MODEL_PROVIDER_EVIDENCE.json`; their LF digests are bound by `../sbom/ner-*.pypi-licenses.json`). On 2026-10-10 the unmeasured Dependabot pin edits (networkx 3.7, filelock 4.0.11, and on Windows MarkupSafe 3.0.4 / setuptools 84.0.0) were reverted to the measured pins: networkx 3.7 requires Python >= 3.12, so the Linux 3.11 lock was uninstallable, and neither edit had wheel/licence evidence. Do not edit pin lines by hand or merge version-only bumps. **Open security residual:** the measured Windows lock pins setuptools 78.1.0 (CVE-2025-47273, a path traversal in `setuptools.package_index`, fixed in 78.1.1). The NER worker never calls `package_index`/`easy_install` at runtime, but the lock must move to setuptools >= 78.1.1 in the next measured re-lock (torch's `setuptools>=77.0.3` allows it; `uv pip compile` for Windows/Python 3.12 resolves with 78.1.1). That re-lock needs a host that can download the locked `torch==2.14.1+cpu` wheel, because the evidence generator requires every locked wheel. A change needs, per platform:

1. Resolve the complete closure for the target interpreter, e.g. `uv pip compile <inputs> --python-version 3.11 --python-platform x86_64-manylinux_2_28` (Windows: `--python-version 3.12 --python-platform x86_64-pc-windows-msvc`), with `--extra-index-url https://download.pytorch.org/whl/cpu` for `torch==2.14.1+cpu`. Respect `huggingface_hub<2` (Transformers 5.13), `mpmath<1.4` (SymPy 1.14) and numpy < 2.5 on Python 3.11.
2. Download that platform's wheels with `pip download --only-binary=:all: --require-hashes`, write one wheel hash per pin, install them into a fresh environment with `--no-index --require-hashes`, run `pip check`, `python -m unittest discover -s ner -p 'test_*.py'` and the real-model probe.
3. Regenerate the evidence from the final lock and wheelhouse with `python scripts/extract-pypi-license-metadata.py --lock packages/privacy/ner/<lock> --wheels <wheelhouse> --output packages/privacy/sbom/ner-<platform>.pypi-licenses.json`, then `pnpm verify:provenance`.
4. Record the new measurement in `../docs/MODEL_PROVIDER_EVIDENCE.json`.

Build a platform-specific, hash-pinned wheelhouse in a connected staging environment, run the real-model acceptance suite, scan its SBOM, then import it into the air-gapped environment. Runtime must have network egress denied at the OS/container level. HF offline flags are defense in depth, not a network sandbox.

Do not substitute a generic PER/ORG/LOC NER model and claim complete ADDRESS support. The defense profile requires PERSON and ADDRESS capabilities **separately for Turkish and English**. Those capability declarations still require independent quality evaluation.
