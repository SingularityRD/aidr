# Data labels, documents and bounded audio in the private service

The configured mTLS text service now exposes these opt-in local operations through the same verified user/device/provider grants. None accepts JSON roles, tenant selection or a caller's declaration of enterprise account/compliance. No original container is sent to a model provider by an operation endpoint. An out-of-scope or over-limit input is refused with HTTP 403, `decision:"block"`, `output:null` and a stable `reason` code (for example `AUDIO_FORMAT`, `DSPM_POLICY_CAPACITY`, `INDEX_CAPACITY`, `DOCUMENT_PARSER_NOT_CONFIGURED`); identity, ACL and policy refusals carry no reason. Parser refusals of an accepted request return `decision:"block"` with the parser's reason (for example `UNSUPPORTED_DOCUMENT`, `PDF_OCR_REQUIRED`). The first-release support scope for these operations is declared in `FEATURE_INVENTORY.json#first_release_scope`.

## Administrator data labels and source ACLs

Set `runtime.dataPolicy:{keyId,key}` (a separate institution-approved 32-byte key, referenced from the existing core OS vault in the configuration sample). Source ingestion and reads are disabled without it, including reads of snapshots stored before a restart. Map the actual signed administrator group to the local `security-admin` role. The example JSON deliberately does not give every user this role.

`TextGatewayClient.synchronizeSource(sourceId,generation,documents)` calls `POST /v1/admin/data-source`. Each document is `{id,text,groups,classification}` with a nonempty authorized group list and one of `public`, `internal`, `confidential`, `restricted`. An authenticated administrator submits a complete snapshot at a strictly increasing generation; incomplete snapshots and ordinary users are denied. Removed IDs receive durable tombstones. This connects institution labels to the real final send and scanner gate, rather than keeping a separate unwired classification database. Data source text is encrypted in the existing state store; the in-memory matching index retains tenant-keyed hashes and never logs its source strings.

The index matches short records as their normalized full token sequence; longer documents use the existing five-token fragment index and its conservative coverage threshold. This is bounded fingerprint matching, not complete lineage or arbitrary paraphrase/OCR recognition. It supports at most 1000 total indexed source documents, 100,000 fingerprints, 8192 normalized tokens and 64 KiB of text per indexed source document (the synchronization request itself accepts up to 512 KiB per document, but a larger source cannot be indexed and is refused), and 65,536 window operations per scan (`INDEX_SCAN_LIMIT` blocks the send). A non-empty snapshot whose complete resulting index would exceed these limits, or contain unsupported content, is refused inside the synchronization transaction with a stable code (`DSPM_POLICY_CAPACITY`, `INDEX_CAPACITY`, `INDEX_CONTENT_LIMIT`, `CONTENT_LIMIT`, `INDEX_DOCUMENT_TOO_SHORT`, ...) and nothing is committed; the previous generation stays in force. Removing a source (an empty snapshot) is always admitted so a store that is already over the supported size (for example, one written by an earlier release) can be repaired; until then the gate fails closed on every send. Do not blindly retry a generation or presume an interrupted call did nothing. Read/repair the actual durable generation using the trusted administrator runtime and recorded audit.

Every source snapshot advances a durable data-policy revision. The final transport and local scanner include that revision in their policy epoch and repeat it after asynchronous scanning and immediately before dispatch. A label update during a pending send denies that send. Restart rebuilds the index from encrypted state. A trusted previous RC process which changes source records without updating this revision must not share the database during rollout; stop older processes first.

`TextGatewayClient.readSource(sourceId,documentId)` calls `POST /v1/source/read`. The existing repository checks signed user groups against the stored document ACL before returning text to the privacy engine. The gate enforces the stored classification directly against the selected destination's policy, including empty and symbol-only content; fingerprint or provenance matches can only raise that classification. An authorized internal reader therefore cannot use this route to release a restricted document toward a provider with a lower permitted classification. The result is only sanitized text or `output:null`, after repeating session and policy checks. This is a local repository/administrator snapshot route. SharePoint, Drive, S3 object fetch, native ACL synchronization and remote deletion are still absent; supply an authorized institution connector which maps actual ACLs and complete listings before claiming those sources integrated. The local directory reader accepts only an existing absolute local directory; any other root (including a URL or remote path) is refused with `SOURCE_ROOT`.

## Actual Office/PDF text reconstruction

Set `documents:{python:<absolute physical Python executable>,workerSha256:<independently approved SHA256 of packaged parsers/worker.py>}`. The worker path is always the packaged parser. Startup executes a real text readiness parse and requires the Linux seccomp sandbox; wrong hashes, missing libraries or unavailable sandbox fail before the listener opens. Use the existing pinned parser dependencies and an institution-approved Linux environment. Windows/macOS hosts do not satisfy this parser profile and their document requests are denied.

`TextGatewayClient.protectDocument(bytes,kind)` calls `POST /v1/document/protect`. It supports the existing parser's digital text PDF, narrow OOXML DOCX/XLSX/PPTX, EML, ZIP and text/code kinds, bounded to 8 MiB input and 512 KiB extracted text with the signed policy's smaller final text limit. The parser blocks unsafe/active content, macros, customXML, encrypted or malformed containers and attachments it cannot safely handle. Scanned PDFs, legacy Office, rich documents with unsupported media, original filenames and original containers never pass. The output is newly reconstructed UTF-8 `text/plain` named `aidr-sanitized.txt`, after the actual defense gate. No fidelity or format-preserving redaction is claimed.

`client.sendDocument(bytes,kind)` performs that reconstruction and then the existing checked final text send. It refuses null/unsupported output and repeats the current identity/policy at final dispatch. The host sample exports `finalDocumentSend`. Digital PDF and plain DOCX were parsed and masked over real local mTLS in the package regression; the customXML Office sample and malformed PDF were denied. Scanned PDF support requires an approved bounded page rasterizer plus all-page OCR/visual acceptance; the current route does not silently fall back to uninspected images.

## Audio boundary and remaining specialist inputs

Setting `audioMode:'silence-all'` enables `client.silenceAudio(bytes)` at `POST /v1/audio/protect`. It accepts at most 1 MiB of the existing PCM16 mono/stereo WAV format, 8–48 kHz and at most 120 seconds, rebuilds a WAV and actually zeroes every PCM sample. It returns Base64 `audio/wav` with `ALL_AUDIO_REMOVED`. Invalid or compressed MP3/M4A/Opus audio is denied. It performs no provider dispatch, ASR, transcript or selective masking. Its regression checks nonzero input samples become zero and a compressed input has no output.

Selective audio needs a real approved ASR model, artifact/environment hashes, validated TR/EN recognition and exact word timestamps bound to the original audio SHA256, plus an authorized human review path for residual voice identity. The existing `AudioPrivacy` interval API remains review-only with `output:null`; no client-submitted transcript can approve an audio upload. Video still lacks the actual bounded decoder/transcoder and independently accepted all-frame OCR, face, handwriting/signature and audio scanners. CAD/steganography need actual specialist detectors and accepted coverage. These routes cannot be completed by granting a placeholder model or a fabricated hardware/authority statement.

## Main MCP callback connection

The optional packaged `mcpPrivacyGuards(new TextGatewayClient(config))` supplies `toolGuard` and `outputGuard` to a trusted main gateway host. Its local-only `POST /v1/protect` uses the same mTLS identity, current signed policy and data revision. It verifies the payload SHA256, binds all supplied gateway context metadata in the response digest and checks cancellation after the wait. It approves only `allow` and byte-identical JSON: a redacted substitute does not approve releasing the original main-gateway payload. It always sets `opaqueInspected:false`; binary/image/audio fields remain denied by the main gateway's own guard contract. Keep that gateway's existing signed tool policy, base scanner and after-await session/toolset checks. The [installable private MCP launcher](MCP_SERVICE.md) now resolves the supported signed public gateway library and injects these callbacks with mandatory routing checks. The dependency goes from this optional private profile to the existing public package; the public package does not depend on private privacy code. Other product exits are outside this explicit profile.
