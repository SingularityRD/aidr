01Problem and solution Singularity AIDR

AI no longer just writes text. It runs commands, changes files and sends data.

Coding agents act with developer credentials; people move data into AI chat every day. Singularity AIDR sits in between: before the action happens and before the data leaves the page.

The agent isn't hacked. It's obeying.

Agents run commands, write files, fetch URLs and call MCP tools. A README, a web page or a tool result they read can steer them into a harmful action.

Customer data is one paste away

Customer records, IBANs, national ID numbers and API keys get pasted into ChatGPT, Gemini and other chat products, often without anyone noticing.

One detection core, four product lines

Product line 1

AIDR for AI coding agents

Every tool call reaches the local decision engine before the host acts, and comes back as allow ask deny.

  • 519 YAML detection rules in 31 files: dangerous commands, credential access, persistence, obfuscation, supply chain; Linux, macOS, Windows.
  • Fail-closed entry points: on an internal error a connector denies the call; a hook the host disabled, did not trust or killed gives no verdict.
  • MCP Gateway scans tool results before the model reads them; the SDK and CLI use the same engine.
  • Toxic flow and AI safety: session attack chains, runaway loops, test sabotage and irreversible actions wait for a person.

Product line 2

AIDR Browser Guard

A Chrome, Edge and Firefox extension that masks sensitive values in prompts, pastes and files before the AI site sees them.

  • Turkish and English personal data: T.C. kimlik (checksum), IBAN (mod-97), phones, emails, payment cards; secrets and API keys.
  • Your own data: company code names and exact-data-match fingerprints of your records.
  • Reversible placeholders ([EMAIL_1]): originals come back in the answer, locally only.
  • Enterprise managed: policy through GPO, Intune or Jamf; counts-only telemetry.

02How it works Singularity AIDR

Decisions are made on the device. Only what you choose goes to the centre.

Agent tool calls and browser prompts pass through the same local engine. The control plane is optional: it distributes policy and collects audit records; enforcement stays on the endpoint.

Capabilities at a glance

Inline verdicts

Allow, ask or deny on every tool call, naming the matched rule and artifact.

Rules as data

519 YAML rules, obfuscated commands included; add or override your own.

Toxic flow

Private data, untrusted content and egress in one session: the final step is held.

Supply chain

npm/PyPI checks, plugin scanning at session start and safe model loading.

MCP Gateway

Tool results scanned before the model reads them; signed server manifests.

Human approval

ask waits for a person in the terminal or console; agents can't self-approve.

Data and secrets

TR/EN IDs, IBANs, phones and cards, checksum-validated; cloud, Git and AI keys.

Agent safety

Loops, sabotage, autonomy escalation, irreversible acts: held or blocked.

AI governance

AI asset register, intake, time-boxed exceptions, four-eyes policy change and a scorecard.

Attack simulation

aidr simulate scores defanged attacks against your settings; nothing is executed.

Managed policy

Browser policy through GPO, Intune and Jamf; central policy for agents.

Audit and SIEM

JSONL/CSV audit export; Splunk, Sentinel and Elastic formats.

03Deployment, security and editions Singularity AIDR

You decide where it runs.

Deployment options

Free

Local mode

Connectors and Browser Guard run on the device. No account, sign-up or server; this is the default.

SaaS

Cloud

Hosted control plane, not live yet: dashboard, enrollment, central policy, SSO/SCIM. Enforcement stays local if it is unreachable.

On-premises

Your infrastructure

The same control plane on Docker Compose or Kubernetes (Helm). Telemetry goes to your server, not to SingularityRD.

Air-gapped

Offline networks

A vendor-signed offline license, signed offline threat and intel packs, and an offline image bundle.

Security and privacy

Local first

Detection and masking happen on the device; the default local mode needs no network access.

Counts, not content

Prompts, file contents and detected values are not sent to SingularityRD; telemetry is per-type counts.

Tenant isolation

Postgres row-level security (RLS) across the multi-tenant control plane.

Identity

SSO with Microsoft Entra ID and SAML 2.0, SCIM provisioning, MFA.

Audit

JSONL/CSV export, SIEM delivery, optional signed local audit log.

Signed content

Policies, rule and intel packs and the offline license are signed with Ed25519.

KVKK · GDPR
Designed to support KVKK and GDPR obligations

Data minimisation, masking of personal data before it reaches third-party AI providers, tenant-scoped retention and legal holds, and data residency through on-prem deployment.

Using AIDR does not by itself meet those obligations.
