## 2. Resuming on another machine

```bash
git fetch origin && git checkout claude/cool-dirac-e44iku
pnpm install
pnpm build                       # DEV build; see pitfalls below
pnpm ci:local --list             # all gates
pnpm ci:local --keep-going --fetch-tools --allow-dirty
pnpm test:e2e:real-host          # needs `claude` on PATH (pinned 2.1.282) + network on first run
```

Pitfalls learned the hard way:

- **Dev vs release bundles.** The `build-release` step of `ci:local` leaves release bundles in
  `packages/*/dist`. A release bundle without trusted keys blocks every event, so the
  real-host tier fails on it. Run `pnpm build` again before any real-host run.
- **Disk.** A full run plus several worktrees can fill the disk. Delete
  `.ci-local/runner-temp` and finished worktrees between runs.
- **Timing tests.** The prompt-protection scan has 2 s budgets. The test now times the scan
  in a separate process so coverage instrumentation is not charged to it, but a heavily
  loaded machine can still push it near the bound.
- **Knip.** Removing an `export` that a parallel branch starts using breaks the build; when
  merging feature branches, re-run `pnpm check` and `knip` on the merged tree.
- **Readiness records** (`FEATURE_INVENTORY.*`, `PRODUCTION_SALES_GAPS.*`) must be regenerated
  with their generators. `FEATURE_ACCEPTANCE.json` and `RELEASE_READINESS_REPORT.md` have no
  generator; the latter is stale (it still says 90 capabilities).
- Cursor and VS Code downloads were blocked in the cloud environment, so those two hosts
  have never been run for real.

## 4. Decisions already taken

- Prompt protection is in the sold scope for Claude Code, Codex, OpenCode and OpenClaw
  (proven on a real host); OpenClaw tool-output quarantine is sold too. Cursor/VS Code are not.
  The verifier only allows adding an interception point to the sold scope when its row is
  `enforced` with a real-host record.
- Browser Guard uses the `declarativeNetRequest` permission (install warning "Block content on
  any page") so users cannot lift admin site bans by withholding host access.
- Agent permission profiles are staged in the dashboard and published by the operator with
  one CLI command; connectors only trust a bundle signed with the operator-held key.
- Approval stays out of band: no connector exposes an approval tool to the agent.

## 5. Security review record

Three internal adversarial reviews have been done and all confirmed findings are fixed with
regression tests (for example `packages/core/src/__tests__/security-review-regressions.test.ts`,
`scripts/approval-requests-postgres.test.mjs`, `scripts/notification-outbox-postgres.test.mjs`).
Documented residual risks: code running as the same OS user with full shell access can still
bypass local controls (`docs/configuration.md`); the second account of the same person can
satisfy four-eyes; DNS rebinding leaves a timing signal on notification delivery.
