## What the implementation wave changed

- AIG CVE/fingerprint/MCP data now uses canonical product IDs, aliases, normalized rules, explicit unevaluated semantics, deterministic compilation, generated counts and full SHA-256 manifest fields.
- The strict source blocker is concrete: the pinned AIG tree contains ten case-collision groups (`Dify/dify`, `LiteLLM/litellm`, and `LobeChat/lobechat` across vuln/vuln_en). The approved fork must rename/deduplicate these paths and regenerate the signed bundle; strict mode must not be weakened to hide the collision.
- AIG sync and readiness paths reject unsigned/stale/incomplete data; core consumers have positive, negative, mixed-case and unsupported-rule tests.
- The AIG bridge has broker/JWT/replay/tenant checks, typed redacted results, idempotency, quotas/leases/cancellation hooks, upload/archive validation, SSRF/egress gates and fail-closed readiness. The upstream worker patch adds unique worker identity, authenticated handshake, registration ordering, frame limits and origin controls.
- Supabase has one ordered migration authority, hybrid tenant tables, immutable tenant IDs, RLS policies, atomic device/seat/webhook RPCs, grants/revokes and cross-tenant negative tests.
- Dashboard team creation now uses an atomic `create_team_tenant` RPC, and generated Supabase types cover the hybrid tenant/member/policy relationships; hosted migration and two-tenant browser proof remain external gates.
- Dashboard-facing Supabase Edge Functions now share an explicit `AIDR_ALLOWED_ORIGINS` CORS/preflight guard (including the Supabase client headers); missing or unlisted browser origins fail closed before auth/database work. The deployed allowlist still requires hosted-environment evidence.
- Device bootstrap, enrollment, API-key, enrollment-token, and waitlist rate-limit storage now fails closed when the counter RPC/table is unavailable; it no longer silently bypasses abuse controls.
- A controlled, synthetic `/demo` route is now available for non-sale customer/investor walkthroughs. It exercises deterministic fixture decisions, evidence redaction, agent inventory, incident timeline and invoice/order framing without invoking Supabase or external commands; it remains accessible in the no-Supabase local fallback while all other dashboard routes fail closed. `pnpm demo:preflight` and the [controlled demo runbook](./controlled-demo-runbook.md) make the boundary explicit.
- The direct-GA dashboard now advertises invoice/order pricing only; checkout, portal and legacy Paddle webhook paths are backend-gated and fail closed unless a separately approved legacy mode is enabled.
- Root Vitest now includes dashboard `.test.tsx` files with a pinned `jsdom` environment; dashboard integration/usage tests are part of the 117-file / 1,948-test evidence set.
- Dashboard routing includes `/pilot`, `/pricing`, `/support`, `/status`, `/security`, `/privacy` and `/terms`; return-to, session errors, onboarding expiry/retry/cancel, masked tokens, router errors, CSP and no-production-fallback contracts are covered by static tests.
- Release E2E is manifest-driven with expected/collected/executed/passed equality, fresh HOME/tenant isolation, redacted JSON/JUnit evidence and fail-closed external evidence requirements for all five connectors, AIG, Supabase and browser gates.
- Release workflows are split into version, RC and promote/rollback/yank paths. Scoped packages are version-aligned at `0.6.0`, publish as `restricted` to `https://npm.pkg.github.com`, and the workflow contains no public npmjs fallback.
- Core/Sentry/logging/audit paths redact sensitive data; the deprecated tracing compatibility API is local-only and emits no telemetry; signed audit checkpoints, retention/deletion manifests, SBOM/provenance and independent evidence verification are implemented.
- First-party license text and package metadata are proprietary and consistent; Tencent/AIG and other third-party attribution remains in `NOTICE`, `THIRD_PARTY_NOTICES` and vendor notices.

## Required closure sequence

1. Create a clean Linux RC checkout; commit/push the reviewed AIG worker patch to the approved fork and update the root gitlink. Run strict case-sensitive AIG verification and compile/sign the data bundle with `SOURCE_DATE_EPOCH`, source tree hash, compiler hash, key ID and expiry.
2. Provision the signing workspace, public fingerprint, SBOM/provenance attestations and protected tag. Build once, then test, sign and publish the same digest; do not rebuild per region.
3. Link a staging Supabase project and deploy the ordered migrations/functions. Run two consecutive resets, N-1 forward migration, generated type diff, two-tenant RLS matrix, device/seat admission races and webhook idempotency.
4. Deploy private AIG bridge/server/worker cells behind broker mTLS or short-lived JWT, shared durable task state, attested disposable sandbox and egress proxy. Run vulnerable/patched fixtures for Infra, MCP, Agent and Jailbreak, including secret canaries, worker forgery, cancellation/outage, incident mapping and cross-tenant negatives.
5. Provision fresh connector lab profiles and scoped provider keys. Execute all 42 real-host tests across the supported Node/host/OS matrix; require `collected = executed = passed`, no skipped/todo/pending, structured hook verdicts for malicious tests and rollback evidence.
6. Deploy the dashboard RC with production Supabase configuration. Run Playwright/axe/console/link/keyboard/mobile/zoom/reduced-motion evidence on Chrome, Edge, Firefox and Safari; attach the deployed revision and route smoke report.
7. Run SAST/SCA/secret/container/IaC/DAST/API-fuzz checks and the independent pentest. Close or formally document every exploitable high/critical finding; no critical may be waived.
8. Complete privacy/legal, enterprise order, SLA/support and private-registry rehearsals. Run the signed customer PoV and two independent dress rehearsals with no hidden manual intervention.
9. Run `node docs/scripts/claim-check.mjs --mode=gate`, have all domain approvers sign the same Commercial Release Manifest, then promote the exact signed RC digest to EU, US and APAC. If any gate or region fails, retain NO-GO and roll back.
