## What can be discussed today

AIDR has connector code that sends observed AI-host tool calls to a shared local evaluator and returns `allow`, `deny` or `ask`. Host invocation and actual side-effect prevention are separate acceptance questions. The intended **five-connector direct-GA scope** in `docs/production-readiness/commercial-go-evidence-registry.json` (COM-010) is Claude Code, Cursor, VS Code, OpenClaw and OpenCode. Codex has preview/engineering coverage, **not** a direct-GA order entitlement. `FEATURE_INVENTORY.md` distinguishes implemented, partial and external-acceptance capabilities; `deploy/native/support-matrix.json` lists six engineering/evaluation rows, including Codex, with interception boundaries and known bypasses. Its legacy `soldConnectorScope` name does not expand the five-connector commercial scope. All six `acceptanceEvidence` arrays are empty, and the matrix decision is `NO-GO`; no connector/host/OS/version combination is approved for a supported customer installation yet. Do not promise coverage of every agent action, endpoint isolation, automatic credential revocation, detection rates or zero false positives.

The intended deployment choices are an AIDR-managed cloud control plane and a customer-hosted control plane. Both require their own exact-release installation, identity, TLS, telemetry, backup/restore, privacy and operator acceptance. The isolated Docker rehearsal (`docs/production-readiness/onprem-install-acceptance-2026-09-23.md`) exercised a synthetic 98-migration, 77-check self-hosted smoke on a Windows development host; `/readyz` correctly remained HTTP 503 because signing, offsite backup, durable queue and certificate evidence were absent. That is neither a signed release nor a cloud or BMC environment result. A cloud pilot URL is not evidence of a GA service.

No approved provider-of-record, price, tax treatment, SLA, support rota, legal terms, region guarantee, independent security assessment or customer reference is held in this packet. The intended 14-day/one-agent cloud trial and both online-cloud and enterprise-invoice sales channels are product decisions, not enabled paid commerce or an approved offer. `pending_finance` is order intake, not an invoice, settled payment or entitlement. Give no purchasing or security questionnaire answer without an owner, exact candidate digest, evidence link, limitation and review date.

## A safe orientation and proposed proof of value

An AIDR operator may walk through architecture and a **disposable, synthetic, explicitly non-production** environment. The customer app no longer contains a synthetic `/demo` page; it redirects to sign-in. `docs/production-readiness/controlled-demo-runbook.md` requires a dedicated test account/tenant, an enrolled disposable agent, actual observed verdicts and incidents, and a stop on missing evidence or exposed secrets. `docs/demo/customer-threat-demo-matrix.md` includes safe inputs and explicitly records a PII/DLP gap. A local `ask`/`deny` response is not proof the host blocked a side effect. Do not substitute static preflight, screenshots or fixture rows for a live host trace.

Before any live customer PoV, obtain written authorization and an Evaluation Charter (`docs/production-readiness/customer-investor-validation-master-plan.md`, §18.3) that fixes the signed candidate, deployment and region, host/OS/version, synthetic or permitted data class, network boundary, safe canaries, stop contact, support interventions, success/failure thresholds, retention and deletion, and buyer/AIDR signers. For each quoted connector the customer independently observes a benign action, safe deny action with absent side effect, disabled/crashed/offline behavior and rollback. For each chosen deployment, verify login/MFA, device enrollment, policy, tenant-negative access, event/export, data destinations, backup/restore and support drill. Record failures and exclusions; optional MCP, AIG, reputation, SIEM, SCIM, billing and response actions stay excluded until individually accepted. The historical v8 worksheet gives the longer scenario and procurement questionnaire.
