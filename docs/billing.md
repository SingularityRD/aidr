# Billing and enterprise orders

The intended commercial model has two separate channels: online payment for cloud-hosted customers, and enterprise quote/invoice for customers including on-premises deployments. Today, only the enterprise invoice request intake is exposed by default; self-service cloud payment remains disabled until its provider and settlement lifecycle passes acceptance. The enterprise invoice/order workflow uses the finance-approved order and payment ledger as its source of truth; the dashboard only accepts tenant-bound requests for additional protected agents. A request is stored as `pending_finance`; it is **not** a paid invoice and does not change the agent entitlement.

The `invoice-entitlement` Edge function and `enterprise_invoice_orders` table accept idempotent requests from an active tenant owner/admin after session and MFA checks. A repeated request ID with changed terms is rejected. Finance has not yet supplied an approved SKU, signed order, provider-of-record ledger, payment receipt or reconciliation. No production flow in this repository may infer payment from a browser request or grant seats from a pending order. Direct SQL changes to `entitlements` are not a supported sales workflow.

An audited Finance-approval transition now records a paid decision and updates the tenant's agent entitlement atomically. This is a local implementation, not proof of a sold or paid lifecycle: no real provider payment, signed customer order, approved SKU or accounting reconciliation has been accepted. Paid seats alone do not admit a tenant or convert a cloud trial into a paid license; for invoiced orders a separately authorized operator must grant a finite licensed admission after verified settlement. The only payment-driven admission path is the audited Stripe plan path described below, and it has not been accepted against a live provider account. Renewal, reduction, cancellation, refund and offboarding must be reconciled and tested against both cloud and self-hosted deployments before sale. Signed entitlement snapshots and the ingest agent-seat limit remain enforcement components, not payment evidence.

Optional Stripe checkout/webhook code exists behind a default-disabled self-service gate. The webhook has local signature/replay tests, but no live account, approved price, webhook registration, portal, invoice retrieval, refund/cancellation or provider reconciliation acceptance. Paddle helpers are legacy and stay disabled. The dashboard does not show invented prices, exchange rates or an empty invoice ledger as a successful lookup.

The implementation boundaries and acceptance scenarios are recorded in [billing-v6.md](production-readiness/billing-v6.md) and the [commercial evidence registry](production-readiness/commercial-go-evidence-registry.json). **T33 and commercial billing approval remain open.**

## Plan catalog and plan admission

Plans, list prices and seat minimums live in `public.plans` (see [pricing.md](pricing.md)); final SKU approval is COM-001. A catalog row never grants anything.

**Card subscription path (self-service builds only).** When `AIDR_ENABLE_LEGACY_SELF_SERVICE_BILLING=true`, `AIDR_BILLING_PROVIDER=stripe` and `AIDR_STRIPE_PRICE_MAP` is set, the `stripe-webhook` function maps a signed subscription's line item to a catalog plan. `AIDR_STRIPE_PRICE_MAP` is a JSON object of Stripe price id to `plan:interval`, for example `{"price_team_m":"team:monthly","price_team_y":"team:yearly","price_business_y":"business:yearly"}`; only `team` and `business` may appear, one price per plan and interval. The webhook then calls the service-role-only `public.apply_stripe_plan_subscription` RPC, which:

- holds the tenant's admission lock and ignores replayed or older provider events for the same subscription;
- **grants** a licensed admission only for an `active`, automatically collected subscription with one mapped plan item, in cloud admission mode, for an active tenant whose purchaser is an owner/admin, with at least the plan's minimum seats and an unexpired paid period. The admission's `grant_reference` is `stripe:<subscription id>`, its seats are `seats × included_agents`, and it expires at the paid period end, so an unrenewed period lapses by itself;
- **never** replaces an active licence with a different reference (for example an invoice/operator licence), and never undoes an operator revocation (trial abuse, offboarding, or a revoked card licence); it records a `conflict` or `rejected` decision instead;
- **revokes** only the admission bound to its own `stripe:<subscription id>` when the subscription is deleted, `canceled` or `incomplete_expired`, and treats that subscription as closed for good;
- **holds** (records the status, grants nothing) for `trialing`, `past_due`, `unpaid`, `paused`, `incomplete` and `send_invoice` subscriptions;
- writes an `admin_audit_logs` row for every decision (`admission.stripe_plan_granted`, `admission.stripe_plan_revoked`, `billing.stripe_plan_conflict`, `billing.stripe_plan_rejected`, `billing.stripe_plan_status_recorded`, `billing.stripe_plan_closed`).

A malformed price map disables plan grants but still lets terminal events revoke. With no price map configured the plan path is off. `billing-checkout` accepts an optional `catalog_plan` (`team` or `business`) and prices it only from the server's price map and the catalog's `self_serve`/`min_seats` terms; checkout itself grants nothing.

**Invoice path (default).** In the default invoice build the Billing page's plan picker files a tenant-bound upgrade request into the enterprise invoice/order workflow (`invoice-entitlement`, reference `plan-request:<plan>[:<interval>]`). It stays `pending_finance` until Finance approves it and an operator grants the licence.

`public.get_tenant_plan(tenant)` is the member-only projection (membership and identity barrier re-checked) that returns the current plan, its source, admission status, admitted agents and connected agents for the Billing page.
