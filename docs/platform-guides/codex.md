# Codex CLI

The Codex connector (`@singularityrd/aidr-codex`) is a native `PreToolUse` command hook
for the OpenAI Codex CLI. It evaluates `Bash`, `apply_patch` and MCP calls with the shared
AIDR detection core before Codex runs them. Verified against `codex-cli 0.141.0`. The
package README ([packages/codex/README.md](../../packages/codex/README.md)) is the full
reference.

## Prerequisites

- **Node.js >= 22.12.0** on the endpoint.
- The approved package version from the private registry
  ([Package Installation](../package-installation.md)).
- For commercial builds: an `agent-config.json` generated by
  `scripts/deployment-prepare.mjs`, deployed as `~/.singularity-aidr/config.json`, with the
  independently delivered Ed25519 artifact-verification public key. The hook refuses to
  start if its signed manifest, verification key or any signed runtime resource is
  missing or changed.

## Installation

```bash
npm install --global @singularityrd/aidr-codex@VERSION
```

Register the hook in `~/.codex/config.toml`:

```toml
[[hooks.PreToolUse]]
matcher = "^(Bash|apply_patch|mcp__.+)$"

[[hooks.PreToolUse.hooks]]
type = "command"
command = "aidr-codex-hook"
timeout = 10

# Prompt protection: secrets block, personal data warns (prompt_protection).
[[hooks.UserPromptSubmit]]

[[hooks.UserPromptSubmit.hooks]]
type = "command"
command = "aidr-codex-hook"
timeout = 10

# Tool-output inspection (poisoned or injected output, leaked secrets, canary values).
[[hooks.PostToolUse]]
matcher = "^(Bash|mcp__.+)$"

[[hooks.PostToolUse.hooks]]
type = "command"
command = "aidr-codex-hook"
timeout = 10
```

or the equivalent `~/.codex/hooks.json` shown in the package README. Event names must
be PascalCase (`PreToolUse`, `UserPromptSubmit`, `PostToolUse`); a lower-case `pre_tool_use` table is
ignored by the host. See [configuration](../configuration.md#prompt_protection) for the
prompt protection behaviour.

**Trust the hook.** Codex drops an untrusted hook without an error, which means no
enforcement. Review and trust it with `/hooks` after installing. Automation that already
vets its hook sources can use `--dangerously-bypass-hook-trust`.

## How it works

```
codex (PreToolUse) ──stdin JSON──▶ aidr-codex-hook ──▶ AIDR core
                                          │
                                          ├─ allow → no output, call proceeds
                                          └─ block → explicit deny + reason
```

- `apply_patch` bodies are inspected, including every `*** Update/Add/Delete File:`
  target, so a write to `authorized_keys` hidden in a patch is caught.
- `ask` is translated into `deny`, because Codex has no working "ask" verb. The
  approval reference travels in the reason text; approval is operator-held and
  out-of-band.
- Internal errors, unreadable input and missing rule directories become an explicit
  deny with a non-empty reason.
- A signed tenant detector policy (DLP and behavioural detectors) can be provisioned at
  `~/.singularity-aidr/detectors/codex.json`. An invalid or required-but-missing bundle
  becomes a deny.

## Host behaviour you must know

Codex decides what happens when a hook misbehaves, and every such case proceeds:

| Hook behaviour | Codex result |
| --- | --- |
| Well-formed `permissionDecision: "deny"` | Blocks the call |
| `permissionDecision: "ask"` | Proceeds (AIDR never emits it) |
| `deny` with an empty reason | Proceeds (AIDR never emits it) |
| Hook crashes, times out or prints malformed JSON | Proceeds |
| Hook not trusted | Never runs |

The remaining fail-open path is the hook process being killed before it writes output.
AIDR on Codex is a guardrail at the hook boundary, not endpoint isolation.

## Scope

- Covered: `Bash`, `apply_patch` and MCP (`mcp__*`) calls before execution. The
  real-host record covers `Bash`; MCP coverage follows the 0.141.0 source and the
  connector's tests.
- Observed, not enforced: `Bash` and MCP tool output (`PostToolUse`). The host source
  replaces a blocked result with the reason, but no real-host run shows it, so no
  pre-model output protection is claimed for Codex.
- Not covered: other local function tools outside the matcher (for example
  `update_plan`), `apply_patch` output, and hosted tools such as web search that do
  not pass through the tool-hook path. Use the
  [MCP Gateway](../../packages/mcp-gateway/README.md) for enforced MCP result inspection.

## Verify

```bash
node scripts/verify-codex-hook.mjs   # blocks a known threat and allows a benign command
aidr-codex-hook --health             # machine-readable capability evidence
```

Repeat host acceptance for every Codex version you deploy; a new host version can
change hook behaviour.

## Real-host acceptance

Recorded by `pnpm test:e2e:real-host` (see [development](../development.md#real-host-e2e-with-a-scripted-mock-model)): the real host binary on linux/x64, AIDR installed from the development build in a disposable HOME, and a scripted loopback mock model in place of a real one. It proves what the host does with AIDR's answer at each boundary, not how a real model behaves or how broad detection is. Record: [`docs/evidence/real-host/codex.json`](../evidence/real-host/codex.json)
(`codex-cli 0.141.0`, `codex exec` with a custom `model_providers` entry and
`--dangerously-bypass-hook-trust` in place of the interactive `/hooks` review).

- `PreToolUse`: `curl … | sh` and `cat ~/.ssh/id_rsa` (an `ask`, sent as `deny`) were
  refused with no side effect; a benign command ran; the same command ran without the hook.
- `UserPromptSubmit`: a prompt carrying a token ended the turn before any model request.
  `codex exec` shows no reason text for this block.
- An internal connector failure (integrity check) blocked; a hook process killed before
  its verdict let the command run, as the table above states.

`PreToolUse` and `UserPromptSubmit` (prompt protection, sold since 2026-09-30) are part of
the sold support matrix (`deploy/native/support-matrix.json`) and are `enforced` in
`deploy/native/interception-matrix.json` on this record only: linux/x64, the development
build and a scripted mock model. Prompt protection needs the `UserPromptSubmit` handler
registered and trusted next to `PreToolUse`; an untrusted, crashed or timed-out prompt hook
lets the prompt through. Codex tool output is not inspected.
